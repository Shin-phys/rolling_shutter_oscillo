# 校正

## 1. なぜ必要か

行の時間間隔 t_row は、機種・解像度・フレームレートごとに違い、公表もされていない。
周波数を数値で出すには、既知の周波数を撮って換算係数を求める必要がある。

フレームレート（コマの間隔）からは求められない。1コマの読み出し時間は、コマの間隔より短いからである（`01-principle.md` の7節）。

## 2. 基準の候補

| 候補 | 内容 | 長所 | 懸念 |
|---|---|---|---|
| A. 基準光 | マイコン（ESP32 など）で LED を 1 kHz で点滅させる。 | 周波数が正確で、縞がはっきり出る。周波数を変えて直線性も確かめられる。 | 基準光源を作る手間がある。 |
| B. 音叉 | 440 Hz などの音叉を逆光で撮る。 | 学校に必ずある。 | 振動が減衰する。輪郭の検出が要る。 |
| C. 照明のフリッカー | 東日本なら 100 Hz。 | 準備が要らない。 | 器具による（直流点灯の照明では縞が出ない）。周期が長く、1コマに入る数が少ない。 |

どれを標準にするかは RS-Q-04 で決める。
学校で配る形を考えると、A を教員が1台用意して全班が順に校正する形が有力である。

## 3. 手順の案

1. 測定に使うのと同じカメラ・解像度・フレームレートにする。
2. 基準を撮る。
3. アプリが縞（または波打ち）の周期 p を行数で求める。
4. 基準の周波数 f_ref を入力すると、行の時間間隔が計算される。

```
t_row = 1 / (f_ref × p)
```

5. 校正値を保存する。
6. 別の既知の周波数を測り、合っているかを確かめる（RS-F-23）。

## 4. 注意

- カメラ（レンズ）を切り替えると、校正値が変わる可能性がある。
- 解像度やフレームレートを変えたら、校正をやり直す。
- 写真と動画で読み出しの速さが違う可能性がある。読み込む素材の種類ごとに校正する。
- 校正値が撮影のたびに安定しているかは要検証（RS-Q-03）。
- 画像の縦横を回転して保存する機種がある。行の向きを取り違えないよう、読み出し方向の判定（RS-F-11）を校正の前に行う。
