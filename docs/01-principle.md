# 原理

## 1. ローリングシャッター

スマホの撮像素子（CMOS）は、画面全体を同時には撮らない。1行ずつ順に読み出す。
このため、画像の行ごとに、写っている時刻がわずかに違う。

| 量 | 記号 | 目安 |
|---|---|---|
| 行と行の時刻のずれ | t_row | 数〜数十マイクロ秒 |
| 1コマの読み出しにかかる時間 | T_read | 約10〜30ミリ秒 |
| 1コマの行数 | N | 解像度による（例：1080行） |

T_read ≒ N × t_row であり、1コマの読み出し方向がそのまま短い時間軸になる。
具体的な値は機種・解像度・フレームレートで変わり、公表もされていないので、校正が必須である（`03-calibration.md`）。

## 2. 見えるもの

### 2.1 点滅する光（点滅モード）

- 点滅する光に照らされた一様な面を撮ると、点滅が縞模様として写る。
- 縞は読み出し方向に直交して並ぶ。
- 読み出し方向の明るさの変化が、そのまま光量の時間変化（波形）である。
- 縞の周期が p 行のとき、周波数は次のとおり。

```
f = 1 / (p × t_row)
```

例

- 照明のフリッカー：交流の周波数の2倍で明滅する。東日本（50 Hz）では 100 Hz。ただし器具による（3節）。
- LED 調光の PWM：点灯と消灯の時間の比が、縞の明暗の幅の比として見える。

### 2.2 振動する物体（振動モード）

- 音叉の腕や弦を、長い向きを読み出し方向に沿わせ、振動の向きが読み出し方向と直交するように置いて撮る。
- 行ごとに違う時刻の位置が写るので、まっすぐな腕や弦が波形に変形して写る。
- 波打ちの周期（行数）から、点滅の場合と同じ式で振動数が出る。

## 3. 照明のフリッカーについての注意

- 直流で点灯する照明（インバータ式の蛍光灯、ちらつき対策をした LED）では、縞がほとんど出ない。
- 古い蛍光灯や安価な LED では、はっきりした 100 Hz（東日本）の縞が出る。
- どの照明で縞が出るかは、教室ごとに確かめる（RS-Q-10）。

## 4. 測定範囲（目安）

| 限界 | 決まり方 | 目安 |
|---|---|---|
| 下限 | 1コマの読み出し時間 T_read の中に、周期が数個以上入ること（f > 数 / T_read）。 | 約100〜200 Hz |
| 上限1 | 露光時間が周期より十分短いこと。露光が長いと縞や波打ちがぼけて消える。 | 露光次第で数kHz |
| 上限2 | 1周期に数行以上が入ること（f < 1 / (数 × t_row)）。 | 十数kHz |
| 上限3 | 動画の圧縮で細かい縞がつぶれないこと。 | 要検証 |

実際には上限1（露光）で決まることが多い見込みである。実際の範囲は実機で確かめる（RS-Q-06）。

## 5. 成立の条件

### 5.1 露光を短くする

- 露光時間が現象の周期より十分短くないと、像がぼける。
- 強い光を当てると、カメラは自動で露光を短くする。逆光のシルエットにすると、背景が明るくなり露光が短くなる。
- 露出を手動で設定できる端末やカメラアプリでは、シャッター速度を 1/4000 秒程度まで短くする。

### 5.2 照らす光をちらつかせない

- 振動体を照らす光そのものがちらつくと、その縞が混ざる。
- 振動モードでは、直流で点灯するライトを使う（`04-shooting-guide.md`）。

### 5.3 自動処理の影響

- 写真モードでは、複数のコマを合成する処理（HDR など）で縞が消えたり乱れたりする可能性がある（RS-Q-05）。
- 動画では、手ぶれ補正が画像をゆがめ、圧縮が細かい縞をつぶす可能性がある。

## 6. 弦を撮るときの注意

- 弦は場所ごとに振幅が違う（腹と節がある）。
- 写る形は「時間波形」と「振動の形（モード）」を掛け合わせたものになる。
- 振動数は正しく読める。波形そのものを議論するなら、全体がほぼ同じ位相で動く音叉の腕のほうが素直である（RS-Q-07）。

## 7. コマとコマの間

- 1コマの読み出しが終わってから次のコマが始まるまでに、空白の時間がある。
- コマをまたいで波形をつなぐことはしない。解析は1コマの中で完結させる。
- 複数コマを使うのは、結果を平均してばらつきを抑えるためだけである。
