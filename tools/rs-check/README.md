# 検証ツール（rs-check）

アプリ本体を作る前に、ローリングシャッターの縞や波打ちが実機で写るか、数値として測れるかを確かめるための道具。
授業で生徒が使う画面ではない。本体の技術構成（RS-Q-08）とは独立させ、依存ライブラリのない静的ファイルだけで作っている。

| ファイル | 内容 |
|---|---|
| `index.html` | 画面 |
| `core.js` | 解析の関数（画面に依存しない） |
| `test/core.test.js` | 合成信号による解析のテスト（`node tools/rs-check/test/core.test.js`） |

## 開き方

- 写真・動画の読み込みだけなら、`index.html` をブラウザで開けば動く。
- ライブカメラには HTTPS が要る。GitHub Pages で公開すれば `https://shin-phys.github.io/rolling_shutter_oscillo/tools/rs-check/` で開ける。

## できること

| 機能 | 内容 | 関係する ID |
|---|---|---|
| 入力 | 写真・動画の読み込み、ライブカメラ（静止して解析、0.5 秒ごとの連続解析） | RS-F-01, RS-F-02 |
| 帯の指定 | 画像の上をドラッグ | RS-F-10 |
| 読み出し方向 | 縦横の両方向で周期性を比べて自動判定。手動でも切り替えられる | RS-F-11, RS-Q-09 |
| 点滅モード | 帯の中を直交方向に平均した明るさの分布から周期、コントラスト、明るい部分の割合 | RS-F-12, RS-F-16 |
| 振動モード | 1行ごとに明暗の境目の位置を求め、変位の波形から周期と振幅 | RS-F-13 |
| 周期の求め方 | FFT（ハン窓、ゼロ詰め、放物線補間）と自己相関の両方を出し、ずれを表示 | RS-F-14, RS-Q-11 |
| 複数コマ | 動画で連続 n コマを解析し、周期の平均と標準偏差を出す。ライブでは直近 20 回 | RS-F-15, RS-Q-03 |
| 校正 | 基準の周波数から t_row を求め、名前を付けて端末に保存。確かめの周波数との誤差 | RS-F-20〜23 |
| 警告 | コントラスト不足、周期性が弱い、周期が少ない・行数が少ない、2つの方法のずれ、読み出し時間がコマの間隔より長い | RS-F-32, RS-F-33 |
| カメラの機能 | ブラウザが報告する `getCapabilities()` と `getSettings()` を表示。露光時間を手動にできる端末ではスライダーを出す | RS-F-03, RS-Q-12 |
| 記録 | 結果を一覧に追加し、CSV で保存。波形も CSV で保存 | RS-F-40, RS-F-41 |

## 検証の手順（`docs/README.md` の引き継ぎに対応）

1. 照明の下で白い紙を、標準カメラの写真と動画で撮る。ツールで読み込み、紙の部分に帯を置く（RS-Q-01, RS-Q-10）。
   - 縞が出れば、自動判定された方向と、1コマあたりの周期数を記録する。東日本の 100 Hz なら、1コマに入る周期数は数個（T_read が 10〜30 ms なら 1〜3 個）になる見込み。
2. 同じものをライブカメラでも撮り、「カメラの機能」を記録する（RS-Q-12）。
3. 音叉を逆光で撮り、振動モードで腕の輪郭1本に帯を置く（RS-Q-01）。
4. 縞の向きから読み出し方向を確かめる。写真を回転して保存する機種かどうかも、縦向き・横向きの両方で撮って確かめる（RS-Q-09）。
5. 動画で連続コマ解析をし、周期のばらつきを見る。日を変えて同じ条件で撮り、校正値の安定性を見る（RS-Q-03）。

記録の CSV は、そのまま `docs/` の検証結果の文書にまとめる素材にする。

## 解析の中身

- 輝度は 0.299R + 0.587G + 0.114B。ガンマ補正は戻していない（周期の測定には影響しないが、コントラストと明るい部分の割合は目安）。
- 周辺減光などのゆるやかなむらは、2次式の当てはめで除き、周期の見当がついたら1周期ぶんの移動平均で除き直す。
- 方向の自動判定：縦横それぞれの分布で自己相関の最初の山の高さを比べる。どちらも 0.2 未満なら「判定できない」と表示する。
- 振動モードの境目：帯の明るさの 5% 点と 95% 点の中間を閾値とし、1行目は最初の境目、以降は前の行に最も近い境目を追う。
